# Kaivo for iPhone and iPad

A SwiftUI app that carries the **Safari Web Extension** built from `plugin/src`. On iOS a web extension can only ship
inside an app, so there is one project with two targets:

| Target | Id | What it is |
| --- | --- | --- |
| `Kaivo` | `$(KAIVO_BUNDLE_ID)` | the app: Today, Feeds, Library, readers, and the sheet that gets the extension switched on |
| `KaivoWidgets` | `$(KAIVO_BUNDLE_ID).widgets` | briefing, highlight and continue-reading widgets |
| `KaivoExtension` | `$(KAIVO_BUNDLE_ID).extension` | the web extension (`plugin/src` with `platforms/ios/manifest.json`, Kaivo brand) |

## The app

Native SwiftUI: `TabView`, `NavigationStack`, `List`, `.searchable`, sheets, `ShareLink`. Do not give bars or lists their
own background (that switches the iOS 26 material off); the brand comes in through `.tint` and the serif reading font.
Own drawing only where iOS has no component (`TopicBubbles`, highlights in `ReaderView`).

**Data.** The app keeps JSON files in the App Group container (`Shared/SharedStore.swift`): `feeds.json` in the format of
the encrypted feed sync, the items per device, `library.json`, and `widgets.json`, a snapshot the widgets read (they never
use the network). Feeds are https only (no App Transport Security exception). Made-up data appears only in debug builds
started with `-KaivoSamples YES`.

**Strings.** Add translations with `scripts/add-strings.py` (or in Xcode); the catalog is the source.

**Screenshots.** `-KaivoStartTab today|feeds|library|widgets` and `-KaivoStartArticle sleep-memory` open a screen in debug
builds; `widgets` shows the widget views, which the simulator cannot place by script.

**Tests.** `xcodebuild … -scheme Kaivo test` (parser, addresses, deep links, shared folder).

## Build

Needs Xcode, Node.js and [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).

```bash
mobile/ios/build.sh            # generate the project and build for the simulator
mobile/ios/build.sh --run      # ... install and start it ($SIMULATOR, default "iPhone 17")
mobile/ios/build.sh --open     # generate and open in Xcode
```

* `project.yml` describes the project; `Kaivo.xcodeproj` is generated and not committed. Change the YAML, not the project.
* Every Xcode build runs `scripts/copy-extension.sh`: it builds the web extension and copies it into the extension bundle,
  so a change in `plugin/src` is in the app after the next build.
* The version comes from `current_version.json` (`scripts/version.sh`, run by `build.sh`). After pulling a release, run
  `build.sh` again before archiving.
* Colours: `design-system/dist/ios/DesignTokens.swift` (`KaivoTokens.accent`, …), generated by `npm run tokens`.
* Icons: `node mobile/scripts/app-icons.mjs ios`. It also draws the two test icons: **DEV** (orange, device builds from
  this Mac) and **BETA** (violet, TestFlight).
* `App/Info.plist` and `Extension/Info.plist` are written by XcodeGen from `project.yml` (not committed).

## Device, TestFlight, App Store

`scripts/upload-testflight.sh` uploads with the BETA icon. **A build for the App Store needs
`scripts/upload-testflight.sh --release`**; never submit a BETA build for review.

1. Copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig` and set `DEVELOPMENT_TEAM`.
2. A free "Personal Team" can run the app on your own iPhone (the profile expires after 7 days). TestFlight and the App
   Store need the paid Apple Developer Program.
3. Decide on the bundle id (`Config/Base.xcconfig`) **before** the first submission: it cannot change afterwards.
4. Check the purchase flow against the App Store Review Guidelines (section 3.1) before submitting: the extension links to
   a web checkout for the Support Pass.

## Switching the extension on in the simulator

Start the app, tap **Open extension settings** (iOS 26.2+) or go to Settings → Apps → Safari → Extensions, turn on Kaivo
and allow websites. Then open an article in Safari. What to check: the Safari list in the repo's `readme.md`.

## Known gaps

* The popup was designed for desktop browsers and has not been checked on an iPhone.
* No context menu, keyboard shortcuts or native notifications on iOS; background work is not persistent.
* What the Safari extension saves does not reach the app yet. No share extension, no background refresh, no feed sync.
* App Groups on a real iPhone need a signing team that allows them; only checked in the simulator.
* Read aloud picks a voice of the text's language (`App/Voices.swift`); one text, one voice.
