# AISH project audit (2026-10-07)

Measured on `plugin/src` (20k lines JS/CSS/HTML), `scripts/`, build and repo layout. Companion to `STYLE_AUDIT.md` (CSS only).

## 1. Biggest risks (fix first)
1. **No tests in the repo.** All ~40 jsdom tests (`test1…test37`, harness) live in `~/t`, outside git and CI. `release.yml` runs no test step. One machine loss = no regression net. → move to `plugin/tests/`, add `npm test`, run in `release.yml` before packaging.
2. **`src/content.js.bak` (81 KB) is tracked** and is a stale copy of the content script. Delete.
3. **Dev copies are `cp` of `src/`**, but `content.js` is an ES-module entry that `scripts/build.js` bundles. A plain copy only works because tests don't load it in a browser. → use the real build (`plugin/build.sh`) for dev folders, or document that dev copies are not loadable.
4. **Dead DOM references.** `getElementById` ids that exist neither in `popup.html` nor are created in JS: `analyticsStatus/TrialRemaining/CompletedRequests/LastModel/Section`, `cloudModelGroup/Teaser` (authManager), `betaPodcastToggle` (settingsManager), `summarizeButton` (popup.js). Either feature remnants (delete code) or missing markup (bug).
5. **16 empty `catch {}` and 20 `console.log`** in shipped code: failures vanish silently; logs leak into users' consoles. → `log.js` wrapper with levels, `catch` at least `debug`.

## 2. Size and structure
| File | Lines | Problem |
|---|---|---|
| `styles.css` | 3162 | one file, sections appended, overrides later rules (see STYLE_AUDIT) |
| `feedManager.js` | 2094 | list, filters, sheets, tags, subs, settings, scroll, search in one module |
| `articleManager.js` | 1379 | history list, cards, detail, tabs, search, graph/report toggles |
| `settingsManager.js` | 1146 | 8 `init*` areas (model, general, LocalSend, backup …) |
| `archiveGraph.js` | 1031 | `renderGraph` alone is 308 lines |
| `content.js` + `content/` | 843 + 1953 | OK structure, `ui.js` has 65 inline styles |

Giant functions (>100 lines): `initMainScreen` 386, `initArticleManager` 337, `renderGraph` 308, `initModelSettings` 220, `initAnalyticsReport` 175, `initLocalSendSettings` 167, `initBackupRestore` 161, `renderStep3` 159, `getAllTextContent` 149, `renderGraphControls` 149, `showArticleDetail` 143, `openFilterSheet` 138, `createChatCompletion` 120. 43 of 529 functions are >60 lines. Most "init" ones are closures that hold all state and wiring: untestable and the reason bugs like the clipped History bar need structural fixes.

**Proposed splits** (pure move, no behaviour change, one commit each, tests between):
- `feedManager.js` → `feed/list.js`, `feed/filters.js` (chips, filter sheet), `feed/tags.js`, `feed/sources.js` (subs, add, OPML), `feed/settingsPanel.js`, `feed/state.js`.
- `articleManager.js` → `history/list.js`, `history/card.js`, `history/detail.js`, `history/tabs.js`, `history/search.js`.
- `settingsManager.js` → one file per `init*` under `settings/`.
- `styles.css` → `css/tokens.css`, `base.css`, `components/*.css`, `screens/{summarize,history,feeds,settings}.css`; keep one `<link>` via build concat.

## 3. Duplication
Same helper defined in several modules instead of one shared file:
- `el`, `btn`, `h`, `section` (feedManager, sendSheet, feedInsights, moodView) → `modules/dom.js`.
- `escapeHtml` in 4 places (settingsManager, pdfExtractor, annotationExporter, digestBuilder) → `textUtils.js`.
- `startOfDay` (feedManager, historyMood), `countWords` (content/core, analyticsManager), `detectPlatform` (extensionApi, settingsManager).
- Two sheet implementations with their own `openSheet/closeSheet` (feedManager vs sendSheet) → one `sheet.js` (matches CSS finding).
- `aiComplete` in `background.js` and `feedAi.js`.
- Root `compatible-tools.json`, `translations.json` duplicated in `plugin/src` (generated by build; the root copies should be removed or ignored).

## 4. UI consistency (JS-generated markup)
- 316 inline-style uses in JS (content/ui.js 65, articleManager 43, podcastManager 38, archiveGraph 32, settingsManager 26, uiManager 18) + 99 in `popup.html`. Anything repeated (tag rows, flex stacks, spacing) → classes/utilities; theme colours inline break dark mode.
- 80 `innerHTML` assignments. Mostly static markup but several interpolate titles/tags/AI output; audit each for escaping (`escapeHtml` exists but isn't consistently used).
- Screen scaffold is now shared for top bars (`.topbar`, `.has-topbar`, `tabbar.js`); next: shared list-card, sheet, segmented, empty-state, section-header so Feed/History/Settings use identical structure.

## 5. Accessibility
- 54 `<button>` in `popup.html` have neither `aria-label` nor `title` (many are text buttons, but icon-only ones need labels); dynamic buttons in JS mostly set `title` only.
- Tabs: `tabbar.js` buttons have `role=tab`; add `role=tablist`/`aria-selected` handling to the feed scope row too and arrow-key navigation.
- Sheets/dialogs: no focus trap or Esc handling confirmed in `sendsheet`/`feed-sheet`; add shared `sheet.js` behaviour.
- Colour contrast not verified for `--text-muted` on glass in dark mode; run an automated check on the token pairs.

## 6. Build, release, repo hygiene
- CI: add test step, CSS/JS lint (stylelint + eslint with `no-empty`, `no-console`), and a size budget (popup JS+CSS gzip).
- `lib/` is 2.7 MB (pdf.js 2.4 MB + d3 276 KB); load pdf.js lazily only when a PDF is summarised (check it isn't in the popup path).
- `docs/i18n/manifest.json` 1.2 MB tracked: generated; consider building in CI instead.
- Locale tooling: `feed-i18n.mjs check` should run in CI so new `T()` strings can't ship untranslated (currently 452 strings x 13 locales, 0 missing).
- Stray/untracked-looking files at root (`extension.png`, `og-share.jpeg`, `fix-paths.mjs`, `changelog.txt`) – move into `assets/` or `scripts/`.

## 7. Suggested sequence
1. Housekeeping (1 hour): delete `content.js.bak`, root duplicates, move tests into repo + `npm test` + CI step, fix/delete the dead id references, log wrapper.
2. CSS plan from STYLE_AUDIT steps 3–5 (dead CSS, component merge, split).
3. Shared `dom.js` / `textUtils` / `sheet.js`; remove duplicates.
4. Split `feedManager`, `articleManager`, `settingsManager` (mechanical moves).
5. Break up the 150+ line functions as they are touched; add unit tests for the extracted pure logic.
6. Accessibility pass (labels, focus trap, tabs keys, contrast check).
