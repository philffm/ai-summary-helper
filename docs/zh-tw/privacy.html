隱私權政策

您的 API Key、文章歷史紀錄與劃線重點皆保存在您的裝置本機。網頁內容僅會發送至您選擇的 AI 服務商 — 若您選擇完全本地運行的模型，資料更絕不會離開您的電腦。

最後更新：2026 年 10 月

本隱私權政策說明 AI Summary Helper 處理哪些資料、傳輸目的地及其原因。簡而言之：您的 API Key、文章歷史紀錄與劃線重點皆僅保留在您的裝置上。網頁內容僅會發送至您選擇連接的 AI 服務商 — 若您選擇完全本地運行的模型，所有資料皆完全不會離開您的本機。我們不投放廣告、不販售資料，且所有核心功能皆無需註冊帳號。

若您不同意本政策的任何部分，請勿安裝或使用本擴充功能。

誰負責管理您的資料

依據 GDPR 第 4 條第 7 款之規定，資料控制者（Controller）為 Phil Wornath。完整姓名與法定送達地址請見 法律聲明；您也可以透過本政策結尾提供的聯絡資訊與我們聯繫。

核心功能無需註冊帳號

使用 AI Summary Helper 進行網頁摘要、重點標記、訂閱 Feed 或保存封存記錄時，完全不需要註冊帳號、登入或提供任何個人資訊。您的 API Key（若使用自有金鑰）以及所有文章歷史記錄，皆妥善儲存於瀏覽器的本機儲存空間中。

只有在使用託管服務時才需要帳號：包含 byphil Cloud（無需自有金鑰即可產生摘要）與 Send to Kindle。登入時只需輸入電子郵件地址及一次性驗證碼。我們會儲存該 Email 地址、您的方案或授權狀態，以及基本用量計數（例如請求次數與 Kindle 發送次數），以便套用方案限制。

我們處理哪些資料及其流向

您的 AI 服務商連線

由您決定摘要的生成方式：

  • 自備金鑰（BYOK） — OpenAI、Google Gemini、Mistral AI、DeepSeek 或自訂端點（Custom Endpoint）。您的 API Key 僅儲存於您的本機裝置（絕不同步，亦絕不會傳送給我們）。您選擇摘要的網頁內容會直接從您的瀏覽器發送至指定的服務商，使用您自己的金鑰並受該服務商的隱私權政策規範。我們無法查看、記錄或儲存這些內容。
  • 透過 Ollama 運行本地模型 — 若您在本地運行模型，網頁內容僅會發送至您自己的電腦。任何資料都不會離開您的裝置。
  • byphil Cloud（可選，付費方案） ——專為不想自行管理 API Key 的使用者提供的代管方案。如果您選擇此方案，您要求摘要的文字會經過我們的後端，由後端透過 OpenRouter 代表您將請求轉發至底層的模型提供商，並回傳摘要結果。這純粹屬於轉發傳輸：我們不會儲存任何網頁內容、網址或摘要。我們在每個帳號下記錄的僅有使用量詮釋資料（Metadata）：已完成的請求次數、Token 用量、上次請求的時間以及使用的模型。帳號本身為選用；無需帳號亦可使用所有其他功能。開啟「偏好歐盟伺服器」設定後，具備歐洲端點的模型將僅在該端點運行，且應用程式會標示哪些模型支援、哪些不支援。這僅限制了模型的運行位置，並未縮減傳輸路徑中的節點：您的文字仍會先經過我們的服務（運行於德國的伺服器），再透過美國公司 OpenRouter 傳送至模型端；此外，朗讀與語音轉文字功能目前不提供歐盟伺服器選項。

授權與訂閱狀態

若您啟用 Pro 授權或 byphil Cloud 訂閱，您的授權金鑰會儲存在本機裝置（絕不同步），並用於向我們的後端伺服器驗證訂閱狀態。基本帳戶/帳單中繼資料由我們的金流處理商與後端負責處理；我們絕不會在伺服器上儲存您的網頁內容或閱讀歷史紀錄。

解除安裝意見回饋

當您解除安裝擴充功能時，Chrome 會在此網站開啟一個簡短的意見回饋頁面。該網址僅包含擴充功能版本以及安裝天數——不含任何識別碼、網頁內容或瀏覽紀錄。您在表單中選擇或輸入的內容（原因、選填意見）將作為事件記錄在我們自建（self-hosted）且不使用 Cookie 的分析工具中，並連同擴充功能版本與安裝天數一起記錄，僅用於改進擴充功能。若您的瀏覽器發送了 Do Not Track 訊號或您已選擇退出數據分析，則不會發送任何資料。此頁面沒有 Email 欄位；若需回覆，請在 GitHub 開啟 Issue。您也可以直接關閉該頁面而不填寫任何內容。

您可以隨時透過「設定 → 資料庫與資料 → 備份與還原」（Settings → Library & Data → Backup & restore）匯出資料。備份檔案預設會略過 API keys、登入資訊、授權金鑰與安裝識別碼；若要包含這些內容需手動確認啟用，系統亦會發出警告，因為任何取得該檔案的人都可以使用這些機密。請妥善保管匯出的檔案以確保隱私，並請留意較舊的備份檔案中可能包含機密資料。在相同位置的「危險區域」（Danger zone）可讓您依類別刪除資料，並會顯示即將清除的項目數量：摘要與封存、畫線醒目提示、訂閱來源 (feeds)、Podcast、API keys／登入資訊／授權、傳送目的地 (Kindle、LocalSend) 以及偏好設定。 刪除所有資料 會清除擴充功能儲存在裝置上的所有資料並將其重設為初始狀態。移除擴充功能亦會刪除其資料。這些操作僅會刪除本機資料。至於您的帳號以及我們在伺服器上保留的紀錄（詳見下方），您可以在 byphil.eu/#account進行管理：您可以在該處匯出資料並刪除帳號。擴充功能與 Android 應用程式均在帳號設定中提供了此頁面的連結。

RSS 訂閱來源

內建的 Feeds 閱讀器會將您的訂閱項目與擷取的內容儲存在本機瀏覽器中——絕不同步，也絕不會傳送給我們。當您新增或重新整理訂閱來源時，擴充功能會直接向發布者的伺服器請求該來源網址，就像您用瀏覽器造訪該網站一樣，因此發布者會看到此請求。我們不會代理、記錄或查看您的訂閱項目或閱讀清單。OPML 匯入作業完全在您的裝置上處理。若您開啟背景檢查功能（預設關閉），擴充功能只會依照您自訂的時間間隔重新請求訂閱來源，僅用於在工具列圖示上顯示計數。為摘要項目產生 AI 摘要的運作方式與摘要任何其他網頁相同：只有在您觸發摘要時，內容才會傳送至您選擇的 AI 提供者。選用的 AI 每日回顧與 AI 語氣評分也是如此：只有在您點擊時，擴充功能才會將文章標題、來源名稱與簡短摘要（非完整全文）傳送給您選擇的 AI 提供者，而產生的回顧內容則會快取在您的裝置上。摘要中的 Podcast 單集會在您按下 Play 時，直接從發布者的伺服器串流播放。

傳送文章：Kindle、LocalSend 與系統分享面板

共有兩種傳送途徑，其中只有一種會經過我們的伺服器：

  • Send to Kindle 會經過我們的伺服器。 Amazon 僅接受來自已核准寄件者的電子郵件文件，因此擴充功能會將文章（標題、摘要、內文、重點標記與來源網址）傳送至 byphil 後端，再由後端將郵件寄送至您設定的 Kindle 電子郵件地址。您只需在 Amazon 帳號中將我們的寄件地址（kindle@byphil.eu）加入已核准的寄件者清單。文章內容僅用於產生並發送該封郵件。Kindle 傳送功能需要登入或具備授權；免費方案包含 3 次傳送額度。
  • LocalSend 與系統分享面板（例如 AirDrop）為點對點直接傳輸。 檔案會直接從您的瀏覽器傳輸到區域網路中選取的裝置，或是傳送至您在系統分享面板中選擇的 App。我們不會介入此過程，也無法查看或儲存這些內容。LocalSend 支援安裝了相容 App 的手機、平板、電腦以及電子書閱讀器。

文庫同步、備份與發佈（選用）

預設關閉，直到您在「設定 → 同步與備份」中新增位置。「位置」可以是您選擇的伺服器上的資料夾（Nextcloud 或其他 WebDAV 伺服器，或相容 S3 的儲存空間如 AWS S3、Cloudflare R2 或 Backblaze B2），也可以是您本機電腦上的資料夾。我們不營運這些伺服器，不參與傳輸過程，也絕不會看到您儲存的內容。

  • 加密位置 讓所有裝置隨時同步你的完整資料庫，或建立安全備份：包含文章、摘要、全文、重點畫線、筆記、收藏集與標籤。所有內容在離開裝置前，都會先於瀏覽器端完成加密（採用 AES-256-GCM，金鑰由你的通行密碼衍生），且檔案名稱均會經過混淆處理。伺服器或同步資料夾僅能讀取加密檔案、檔案大小與變更時間。由通行密碼衍生的金鑰只會保留在此瀏覽器的本機儲存空間中，以便在背景持續同步。若你使用系統建議的隨機單字組合，這些單字也會儲存在本機，方便你隨時在該處的設定中查看；若為自行設定的通行密碼則絕不儲存。上述任何金鑰或密碼資訊皆不會被同步或納入備份。若遺失通行密碼，包含我們在內的任何人都無法讀取你的檔案。
  • 明文讀取位置 發佈明文檔案（若有需要，也可包含輕量檢視頁面），供您自己的網站或工具使用。僅有符合您所設標籤篩選條件的文章才會發佈。除非您在危險區域（Danger Zone）手動啟用，否則筆記、提醒事項與文章全文絕不會被發佈；一旦啟用，任何能開啟該資料夾的人皆可閱讀這些內容。
  • 傳輸方式。 請求會透過 HTTPS 從您的瀏覽器直接發送到您輸入的位址，並使用您提供的登入資訊或存取金鑰。該登入資訊僅儲存在本機，絕不同步，且除非您主動選擇，否則不包含在備份中。伺服器營運者能看到您的 IP 位址以及同步時間。
  • 本機電腦上的資料夾 使用瀏覽器的資料夾存取權限。由您選擇資料夾，瀏覽器會向您請求權限（重新啟動後可能會再次詢問）。我們僅保留瀏覽器對該資料夾的控制代碼（handle）。無論您使用何種工具將該資料夾同步至其他裝置（如 Syncthing、iCloud Drive、Dropbox），均適用該工具各自的隱私權條款。

電腦上的 AI 應用程式 (MCP)

預設為關閉。當您開啟「設定」→「AI 應用程式 (MCP)」時，您所連線的電腦 AI 應用程式（例如 Claude Desktop、LM Studio、Cursor 或 VS Code）即可讀取您允許的資料庫內容：已儲存的文章及其摘要與重點標記；若您開啟相應選項，還包括文章全文、訂閱來源項目，以及將連結儲存至收件匣。資料會從您的瀏覽器經由電腦上的小型輔助程式（aish-mcp）傳送至該應用程式。資料絕不會經過我們的伺服器，我們也絕不會看到。輔助程式僅接受來自您本機電腦的連線並需要配對碼；它不儲存任何文章，也不記錄轉發的內容。含有您排除標籤（private ，預設值）的文章絕不會被分享。擴充功能會在您的裝置上保留最近 50 次呼叫的清單（包含工具名稱、時間與結果數量，不含內容），您可以在同一個設定面板中查看。AI 應用程式隨後向其模型傳送哪些內容，取決於您選擇的應用程式與模型：若使用本地模型，任何資料都不會離開您的電腦。您可以隨時關閉此設定或選取「中斷連線」。

分析與 Cookie

簡短摘要： 本網站設定 零 Cookie ，且不使用廣告或跨網站追蹤器。我們使用自行託管的 Matomo 統計匿名造訪次數，您可以隨時關閉此功能。

瀏覽器擴充功能本身不包含任何數據分析、遙測（Telemetry）或追蹤代碼。 它唯一的網路請求只會發送至：您設定的 AI 提供商、您訂閱的 RSS 摘要來源、您要求擷取的網頁、您設定用於文庫同步、備份或發佈的伺服器，以及（若有使用）用於 byphil Cloud、登入、授權檢查與 Send to Kindle 的 byphil 後端。

我們衡量的項目

頁面瀏覽量、頁面語言、推薦來源（Referrer）、概略的國家/瀏覽器/裝置類型，以及您與網站哪些部分進行互動（例如點擊「加到 Chrome」、價格切換開關、常見問題項目、滾動瀏覽的區塊，以及 Bookmarklet 產生器的操作步驟）。事件中絕不包含電子郵件地址、API Key、一次性驗證碼、網頁內容或文章資料。

配置方式

Matomo 運行在我們自己的伺服器上（位於德國的 analytics.philwornath.de），而非第三方託管。它在停用 Cookie 且不進行瀏覽器特徵指紋識別的情況下載入；IP 位址在儲存前均已匿名化；不會指派任何使用者 ID 或跨網站識別碼，因此無法跨天或跨裝置串聯造訪紀錄。我們絕不販售或與第三方分享這些資料。

由於我們不會為了追蹤目的在您的裝置上儲存或讀取任何資訊，此項統計是基於我們了解網站使用情況的正當利益（GDPR 第 6 條第 1 款 (f) 項），且依據德國 TDDDG 第 25 條 / 歐盟 ePrivacy 指令，無需跳出 Cookie 同意橫幅。您有權隨時提出異議（GDPR 第 21 條）。

您的選擇

如果您的瀏覽器傳送了 Do Not Track 或 Global Privacy Control，分析功能將會自動關閉。您也可以透過 數據分析設定 手動退出（在每個頁面的頁尾也能找到此選項）。

儲存在您瀏覽器中的內容

僅儲存功能性偏好設定，絕不用於追蹤： aish_analytics （您的退出偏好設定）、 aish_analytics_notice （記錄您已關閉通知訊息），以及若有使用時的外觀主題選擇、語言建議關閉狀態和 Bookmarklet 產生器設定。這些資料只會保留在您的裝置上，絕不會傳送給我們。
