产品动态 · 2026 年 10 月

你的 Key。你的模型。你的数据。

大多数 AI 工具都会在你与模型之间架设一层专属服务器。本文将探讨去掉这个中间层后会发生什么变化，以及哪些环节依然取决于你自己的选择。

所有 AI 摘要的基本逻辑都一样：发送文本，接收结果。决定你是否能信任该工具的核心，在于谁处于数据传输的中间环节。在许多产品中，中间往往存在一个第三方服务器，你阅读的内容必须经过它，才能传递给你并未亲自选择的模型。

在此处，“自带 API key”究竟意味着什么

你在自己信任的供应商处生成 API key，粘贴进 AI Summary Helper 并选择模型。当你对网页生成摘要时，插件的后台 Worker 会将文本直接发送给该供应商，并以流式传输返回结果。在使用你自己的 API key 时，整个链路中没有任何 AI Summary Helper 的服务器介入。

你也可以将它指向本地运行的模型（例如通过 Ollama）。在这种情况下，网页文本完全不会离开你的电脑。

你的 API key 保存在哪里

你的 key 保存在浏览器的插件本地存储中，而非同步存储。这意味着它不会通过浏览器账号同步到其他设备。相应地，你需要在每个浏览器上单独配置一次。这些 key 仅用于与你所配置的服务商进行通信。

这种机制能保护什么，不能保护什么

我们需要客观明确这一点：自带 API key 只是移除了中间商服务器，但并没有省去模型提供商——你发送给云端托管模型的任何内容，依然受该提供商的服务条款与数据保留策略约束，因此请务必查阅相关条款。只有本地模型才能将文本完全留在你的设备上，不过本地模型通常比云端模型体量更小、响应更慢。

该项目完全开源，你无需盲目信任任何承诺。所有处理 API key 与请求的代码都在代码仓库中，随时可供查阅与审计。

选择适合你的配置方案

  1. 日常阅读： 选择一家条款符合你预期的云端托管模型服务商。速度快、质量高，且 API key 由你全权掌控。
  2. 敏感内容： 选择本地模型。虽然速度较慢、能力稍弱，但任何数据都不会离开你的设备。
  3. 对比探索： 配置多个服务商，并在同一篇文章上对比它们的输出。这是了解哪种模型最适合处理哪类文本的最快方式。

重点不在于哪种配置方案绝对正确，而在于选择权始终在你手中。
