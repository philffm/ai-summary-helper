읽기 라이브러리를 Nextcloud, S3 또는 로컬 폴더에 암호화하여 동기화하는 방법

내가 지정한 위치에 저장되고 내 암호화 키로만 열어볼 수 있는 저장된 글, 요약, 하이라이트, 메모. 별도 계정 가입 없이 10분이면 설정할 수 있습니다.

요약 가이드 AI Summary Helper에서 다음 경로로 이동하세요: 설정 → 동기화 및 백업 → 위치 추가, 그 다음 Nextcloud/WebDAV, S3 호환 스토리지 또는 컴퓨터의 로컬 폴더를 선택하고 제안된 암호 문구(Passphrase)를 그대로 보관하세요. 모든 데이터는 업로드되기 전 브라우저 내에서 안전하게 암호화됩니다. 두 번째 컴퓨터에서는 동일한 위치를 추가하고 암호 문구를 입력하기만 하면 됩니다. 설정은 이것으로 끝입니다. 이 페이지의 나머지 부분에서는 스토리지 유형별 안내, 동기화 항목, 문제 해결 방법을 다룹니다.

왜 이렇게 해야 할까요? 읽기 라이브러리는 평생 간직할 가치가 있지만, 특정 서비스는 언제든 사라질 수 있기 때문입니다 (자세한 내용 보기). 내가 소유한 스토리지에 동기화하면 라이브러리가 특정 앱이나 계정의 서비스 종료에 영향받지 않고 영구적으로 유지됩니다.

동기화되는 항목과 제외되는 항목

  • 동기화 대상: 저장된 글의 전체 본문 및 요약, 태그, 하이라이트, 작성한 메모와 댓글, 컬렉션.
  • 동기화 제외 대상: API 키, 로그인 정보, 동기화 로그인 자격 증명, 기기별 설정. 백업 및 동기화 시 보안을 위해 의도적으로 제외됩니다.
  • 페이지당 단일 글: 두 대의 컴퓨터에서 같은 페이지를 저장한 경우, 하나의 글로 병합됩니다(태그 및 누락된 필드가 통합됨).
  • 필드 단위 편집 병합: 한 컴퓨터에서 제목을 수정하고 다른 컴퓨터에서 태그를 추가해도 둘 다 유지됩니다. 두 기기에서 동일한 필드를 수정한 경우, 더 나중에 변경된 내용이 모든 기기에 우선 적용됩니다.

1단계: 스토리지 위치 선택

Nextcloud 또는 기타 WebDAV 서버

Nextcloud를 직접 운영 중이거나 호스팅 서비스를 사용하고 있을 때 적합합니다(다수의 유럽 제공업체에서 지원). 세 가지 정보가 필요합니다:

  1. 파일 주소. Nextcloud의 경우 다음과 같은 형태입니다: https://your-server/remote.php/dav/files/your-username/. Nextcloud에서 다음 메뉴를 열고 파일 → 설정 표시된 WebDAV 주소를 복사하세요.
  2. 사용자 이름.
  3. 기본 비밀번호가 아닌 앱 비밀번호. Nextcloud 설정: 설정 → 보안 → 기기 및 세션 → 새 앱 비밀번호 생성. 접근 권한을 해제하고 싶을 때는 해당 항목만 삭제하면 됩니다.

다음과 같이 폴더 이름을 지정하세요: aish-sync. 폴더가 자동으로 생성됩니다. 다른 WebDAV 서버(다양한 NAS 기기, ownCloud 등)도 주소 형식만 다를 뿐 동일하게 작동합니다.

S3 호환 버킷

AWS S3, Cloudflare R2, Backblaze B2, MinIO 등 오브젝트 스토리지를 선호할 때 적합합니다. 버킷을 생성한 후, 다음 권한을 가진 액세스 키를 생성하세요: 이 버킷 전용 키 (읽기, 쓰기, 목록 조회, 삭제 권한). 계정의 루트/메인 키는 절대 사용하지 마세요. 확장 프로그램에서 엔드포인트 주소(예: https://s3.eu-central-1.amazonaws.com 또는 서비스 제공업체에서 안내하는 주소), 버킷 이름, 리전(제공업체에서 요구하지 않는 경우 기본값 유지), 액세스 키 ID 및 시크릿 키를 입력합니다.

컴퓨터의 로컬 폴더

Syncthing, 데스크톱 동기화 클라이언트, iCloud Drive, USB 드라이브 등 기기 간 폴더 동기화 도구를 이미 사용 중일 때 적합합니다. 다음을 선택하세요: 이 컴퓨터의 로컬 폴더 그리고 새로 만든 빈 폴더를 선택하세요(예: Documents/AISH-sync). Chrome은 바탕화면, 문서, 다운로드 폴더 자체를 직접 지정하는 것을 허용하지 않으므로 하위 폴더를 지정해야 합니다. 이 방식은 PC 환경의 Chrome 및 Edge에서 지원됩니다. 참고 사항: 브라우저 재시작 후 폴더 접근 권한을 다시 요청할 수 있으며(설정 화면에 버튼 표시됨), 브라우저가 실행 중일 때만 폴더 동기화가 유지됩니다.

2단계: 암호화 선택 및 암호 단어 보관

위치를 추가할 때 암호화됨 가 기본 선택되어 있으며 내 기기 간 동기화 가 목적으로 설정됩니다. 확장 프로그램에서 6개의 무작위 단어로 구성된 암호 문구를 제안합니다. 마음에 드는 조합이 나올 때까지 다른 단어 제안 버튼을 누르거나 직접 입력할 수도 있습니다(최소 12자 이상, 보안 수준이 낮으면 힌트 제공).

연결 후 6개 단어가 한 번 표시됩니다. 이 단어들을 비밀번호 관리자에 저장하세요. 복사 버튼을 누르면 하이픈(-)으로 연결된 형태로 클립보드에 복사되어 설정 파일이나 메시지 앱에 붙여넣기 쉽습니다. 이 암호 문구만 있으면 어떤 기기에서든 위치를 열 수 있지만, 분실 시 개발사를 포함해 그 누구도 파일을 복구할 수 없습니다. 처음 설정한 컴퓨터에서는 해당 위치 설정의 암호 문구 보기 메뉴에서 다시 확인할 수 있습니다. 직접 암호 문구를 입력한 경우에는 어디에도 저장되지 않으므로 확장 프로그램에서 다시 확인할 수 없습니다.

스토리지 제공업체가 확인할 수 있는 정보: 암호화된 파일명과 암호화된 파일 내용, 파일 개수, 파일 크기, 변경 시점뿐입니다. 제목, 링크, 본문 내용은 전혀 볼 수 없습니다. 라이브러리는 기기를 떠나기 전 브라우저 내에서 AES-256-GCM으로 안전하게 암호화됩니다.

3단계: 두 번째 컴퓨터 추가

  1. 확장 프로그램을 설치하고 다음 경로로 이동하세요: 설정 → 동기화 및 백업 → 위치 추가.
  2. 동일한 서버 정보를 입력합니다(또는 동일한 폴더 선택).
  3. 확장 프로그램이 폴더에 이미 암호화된 라이브러리가 있음을 감지하고 암호 문구를 요청합니다. 대소문자 구분 없이 공백이나 하이픈으로 구분하여 입력하면 됩니다.
  4. 기존 라이브러리에 연결하면 현재 컴퓨터의 라이브러리와 폴더의 데이터가 병합되며 충돌 시 폴더 데이터가 우선하므로, 먼저 이 기기의 백업을 생성했는지 확인을 요청합니다. 다음을 이용하세요: 지금 백업 만들기.
  5. 다음 버튼을 누르세요: 연결. 라이브러리 용량이 큰 경우 첫 동기화에 다소 시간이 걸릴 수 있으며 화면에 진행 상태가 표시됩니다.

백업 전용, 복원 및 게시

  • 백업 전용 모드 다음을 선택하면 백업 전용 대신 내 기기 간 동기화 컴퓨터가 해당 위치에 쓰기만 수행하고 읽어오지는 않습니다. 필요할 때 위치 설정에서 복원하세요. 모든 데이터를 다시 가져오며, 현재 컴퓨터와 데이터가 다를 경우 저장 위치의 데이터가 우선 적용됩니다. 어떤 데이터도 삭제되지 않습니다.
  • 웹사이트에 게시 또 다른 저장 위치 유형인 읽기 가능 (Readable)는 태그가 지정된 글에 한해 웹사이트 게시용 일반 텍스트 파일을 생성하며, 선택적으로 뷰어 페이지도 함께 제공합니다. 해당 폴더에 접근할 수 있는 사람은 누구나 읽을 수 있으므로 직접 활성화하지 않는 한 메모와 전체 본문은 제외됩니다. 개인적인 데이터에는 읽기 가능 위치를 사용하지 마세요.

문제 해결

"폴더 접근 권한 다시 허용"

브라우저를 재시작하면 폴더 접근 권한이 초기화됩니다. 다음 메뉴 상단의 버튼을 누르세요: 동기화 및 백업. 계속 실패하는 경우 Chrome 보호 폴더(바탕화면, 문서, 다운로드 또는 홈 폴더)일 수 있으므로 직접 만든 하위 폴더를 선택하세요.

"서버에서 사용자 이름과 비밀번호를 수락하지 않았습니다"

Nextcloud의 경우 앱 비밀번호를 사용하세요. 주소가 사용자 이름 폴더로 끝나는지 확인하고, 2단계 인증이 앱 비밀번호를 차단하고 있지 않은지 확인하세요.

"잘못된 암호 문구"

단어를 확인하세요. 대소문자, 공백, 하이픈은 상관없지만 모든 단어가 정확해야 합니다. 이미 설정된 컴퓨터에서 위치 설정을 열고 다음 버튼을 누르세요: 암호 문구 보기. 모든 기기에서 암호 문구를 분실한 경우 누구도 파일을 열 수 없습니다. 여기서 위치를 삭제하고 새로 생성한 뒤 현재 컴퓨터의 라이브러리부터 다시 시작해야 합니다.

대량 삭제 대기 알림이 표시되는 경우

다른 기기에서 많은 글을 한 번에 삭제한 경우, 실수로 라이브러리가 비워지는 것을 방지하기 위해 일부만 먼저 적용하고 나머지는 사용자에게 확인을 요청합니다. 확인 후 버튼을 눌러 적용하세요.

몇 달 동안 사용하지 않은 컴퓨터

약 3개월이 지난 컴퓨터는 그동안 변경된 내용만 전송하고 스스로 삭제 작업을 수행하지 않으므로, 다른 곳에서 삭제된 예전 글이 실수로 복원되지 않습니다.

자주 묻는 질문

별도 계정 가입이 필요한가요?

아니요. 동기화는 브라우저에서 사용자가 입력한 스토리지로 직접 연결됩니다. 저희는 별도의 동기화 서버를 운영하지 않습니다.

스마트폰에서도 사용할 수 있나요?

Android에서는 가능합니다. 컴패니언 앱( GitHub 릴리스의 APK 파일, 아직 Google Play에는 출시되지 않음)을 설치한 후 다음 메뉴에서 라이브러리에 참여할 수 있습니다: 설정 → 라이브러리 동기화. 가장 빠른 방법은 코드를 사용하는 것입니다. 브라우저에서 위치 설정을 열고 다음 버튼을 누르세요: 스마트폰용 코드 표시 그리고 코드를 스캔하세요. 서버 로그인 정보가 포함되어 있으므로 반드시 본인의 스마트폰으로만 스캔해야 합니다. 스마트폰 앱에서는 저장된 글과 요약, 하이라이트를 확인할 수 있으며 메모는 양방향으로 동기화됩니다. 스마트폰에서 요약한 페이지와 표시한 구절도 라이브러리에 추가되지만, 라이브러리에 아직 없는 페이지만 추가되며 브라우저의 기존 텍스트는 절대 덮어쓰지 않습니다. 현재 iPhone 앱은 지원되지 않습니다.

여러 개의 저장 위치를 사용할 수 있나요?

네, 가능합니다. 컴퓨터 간 동기화를 위한 암호화 위치 1개와 다른 서비스 제공업체에 백업 전용 위치 1개를 구성하는 방식이 자주 사용됩니다.

라이브러리를 클라우드에 저장해도 안전한가요?

스토리지 제공업체에는 암호화된 파일만 저장되므로 대부분의 환경보다 안전합니다. 다만 암호 문구와 기기 자체의 보안 수준에 영향을 받습니다. 다음 문서를 확인하세요: 투명한 한계점 안내(암호화 방식에 대한 독립적 보안 감사는 아직 받지 않았다는 점을 포함합니다).
