आपकी Key. आपका Model. आपका Data.

ज़्यादातर AI tools आपके और model के बीच में एक server लगा देते हैं। जानिए जब बीच में कोई server नहीं होता तो क्या बदलता है, और क्या चीज़ें अभी भी आपके कंट्रोल में रहती हैं।

हर AI summary का एक ही बेसिक प्रोसेस होता है: कुछ text भेजा जाता है, और response में summary वापस आती है। लेकिन आप टूल पर कितना भरोसा कर सकते हैं, यह इस बात पर निर्भर करता है कि बीच में कौन बैठा है। कई प्रोडक्ट्स में बीच में कंपनी का server होता है, और जो कुछ भी आप पढ़ रहे होते हैं वह आपके चुने बिना किसी थर्ड-पार्टी model तक पहुँचने से पहले उस server से होकर गुज़रता है।

यहाँ “bring your own key” का क्या मतलब है

आप अपने भरोसेमंद provider से एक API key बनाते हैं, उसे AI Summary Helper में पेस्ट करते हैं, और अपना मनपसंद model चुनते हैं। जब आप कोई पेज summarize करते हैं, तो extension का background worker सीधे उस provider को text भेजता है और response stream करता है। आपकी खुद की key के लिए AI Summary Helper का कोई भी server बीच में नहीं आता।

आप इसे अपनी मशीन पर Ollama जैसे टूल्स के ज़रिए लोकल चल रहे model से भी कनेक्ट कर सकते हैं। उस केस में, zero recurring cost के साथ offline on-device execution होता है और पेज का text आपके कंप्यूटर से कभी बाहर नहीं जाता।

आपकी key कहाँ स्टोर होती है

आपकी key आपके browser के local extension storage में स्टोर होती है, synced storage में नहीं। इसका मतलब है कि यह आपके browser account के ज़रिए दूसरे डिवाइसेज़ पर कॉपी नहीं होती। बस आपको इसे हर browser में एक बार एंटर करना होता है। Keys का इस्तेमाल केवल उसी provider से कनेक्ट करने के लिए होता है जिसके लिए आपने उन्हें कॉन्फ़िगर किया है।

यह किस चीज़ को सुरक्षित रखता है और किसे नहीं

इस बात को साफ़ तौर पर समझें: अपनी API key इस्तेमाल करने से बीच का बिचौलिया हट जाता है। लेकिन यह model provider को नहीं हटाता—आप hosted model को जो भी भेजते हैं, वह उस provider की terms और retention नियमों के तहत आता है, इसलिए उन्हें ज़रूर पढ़ें। केवल local model ही text को पूरी तरह आपकी मशीन पर रखता है, हालांकि local models आम तौर पर hosted models की तुलना में छोटे और धीमे होते हैं।

यह प्रोजेक्ट पूरी तरह open source है, इसलिए आपको किसी भी बात पर बिना देखे भरोसा करने की ज़रूरत नहीं है। keys और requests हैंडल करने वाला सारा कोड repository में मौजूद है, और आप इसे खुद पढ़ सकते हैं।

सही setup चुनना

  1. रोज़मर्रा की रीडिंग के लिए: ऐसे provider का hosted model जिसकी terms से आप सहज हों। तेज़, बेहतरीन quality, और key आपके कंट्रोल में।
  2. सेंसिटिव डेटा के लिए: एक local model। भले ही यह थोड़ा धीमा हो, पर zero cost और पूरी प्राइवेसी के साथ कोई भी डेटा आपकी मशीन से बाहर नहीं जाता।
  3. एक्सपेरिमेंट करने के लिए: एक से ज़्यादा providers जोड़ें और एक ही आर्टिकल पर उनके जवाब compare करें। यह जानने का यह सबसे तेज़ तरीका है कि किस तरह के टेक्स्ट के लिए कौन-सा model बेस्ट है।

ज़रूरी यह नहीं कि कौन-सा setup सही है, बल्कि यह है कि इसका फ़ैसला हमेशा आपके हाथ में रहता है।
